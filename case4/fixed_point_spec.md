# 固定点契约（RGB565/RGB888）

本阶段统一采用 BT.601 的 Q8 整数近似：

```text
Y_acc = 77*R8 + 150*G8 + 29*B8
Y8    = (Y_acc + 128) >> 8
```

其中 `R8/G8/B8` 是已经扩展到 8 bit 的无符号分量。RGB565 不直接把
5/6 bit 数值代入公式，而是先做全范围扩展：

```text
R8 = {R5, R5[4:2]}
G8 = {G6, G6[5:4]}
B8 = {B5, B5[4:2]}
```

这避免了把 RGB565 的编码量化误差重复放大到灰度计算中。

## 误差定义

以连续 BT.601 参考值

```text
Y_ref = 0.299*R8 + 0.587*G8 + 0.114*B8
```

作为真实亮度，检查硬件输出 `Y8` 与 `Y_ref` 的绝对误差。`verify_fixed_gray.py`
对全部 65,536 个 RGB565 码字和全部 16,777,216 个 RGB888 颜色组合做了穷举检查：

| 输入格式 | 样本数 | 最大连续误差 | 平均连续误差 | 结论 |
|---|---:|---:|---:|---|
| RGB565 扩展到 RGB888 | 65,536 | 0.931 LSB | 0.278 LSB | 通过 |
| RGB888 | 16,777,216 | 0.945 LSB | 0.276 LSB | 通过 |

因此该系数在题目常见的 RGB565/RGB888 输入下满足“量化误差低于 1 LSB”。
这里的 RGB565 误差基准是标准位复制后得到的 RGB888 码值；RGB565 本身从
5/6 bit 采样造成的信息量化误差不属于灰度系数近似误差。若摄像头采用
BGR 或字节交换顺序，必须在输入适配层先纠正通道/端序。

需要区分两种比较：如果把浮点参考值也先独立四舍五入到整数，再逐码比较，两个
舍入边界可能相反，少数样本会相差 1 个输出码；这不等同于连续量化误差超过
1 LSB。RTL 与 Golden Model 应以同一条整数公式做 bit-exact 比较。

## RTL 算术要求

* `Y_acc` 使用至少 17 bit unsigned（最大值 `77×255+150×255+29×255=65,280`）。
* 加 128 后再右移 8 位，不能截断后再加偏置。
* 所有乘法项先扩展到 17 bit 再相加，避免 8 bit 中间溢出。
* RGB565 的字段顺序和端序必须在摄像头适配层固定；算子内部只接收 RGB888。
* 若将来改成更高精度 Q10/Q12，必须同步更新 Golden、HEX 向量和 RTL 常数，不能混用。

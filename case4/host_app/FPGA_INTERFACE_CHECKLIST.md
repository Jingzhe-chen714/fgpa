# 给 FPGA 同学的接口与验收清单

目标：电脑设置阈值后，FPGA 按新增 [V1 协议](PROTOCOL_V1.md) 回复“已接受”和“已生效”，电脑读取到图像处理当前真正使用的阈值。

**本次交付是电脑端软件与模拟设备，不包含已完成的 FPGA UART RTL、易灵思工程或实板验证。下列项目需要由板级工程实现并逐项验收。** 现有 Sobel 核心、默认 11 位阈值及 `>= threshold` 判断行为保持不变。

## 板级信息先确认

| 需要交接的信息 | 负责人填写 |
|---|---|
| 开发板型号、版本 | 待填写 |
| 实际 Efinity 工程和顶层模块路径 | 待填写 |
| FPGA 时钟频率、时钟来源、复位极性 | 待填写 |
| UART RX/TX 端口和管脚约束 | 待填写 |
| USB 转串口芯片及实际 COM 口 | 待填写 |
| 波特率、分频方式和误差 | 待填写；新协议建议 115200、8N1 |
| UART 与图像处理是否跨时钟域 | 待填写 |
| FPGA 复位后的实际阈值 | 待填写；不要从模拟初始值 320 推断 |
| 固件版本或源代码提交号 | 待填写 |
| 图像停止、未启动或复位时的待处理更新策略 | 待填写 |

开发板 UART Demo 可以用于核对引脚和基本收发，但 UART 回显正常只验证字节传输，不代表已经支持命令解析或参数更新。若采用外置 USB 转 UART，核对电平兼容性、TX/RX 交叉和共地；优先使用板卡已有串口连接方案。

## 需要实现的逻辑

| 模块或状态 | 最小责任 |
|---|---|
| UART RX/TX | 按双方相同参数收发原始字节；接收端有必要缓冲，回复帧不可相互穿插 |
| 帧解析与 CRC | 查找 `A5 5A`，累计固定 10 字节，验证 CRC、版本、非零序号和参数，支持噪声后重新同步 |
| 请求分发 | 实现 PING、SET_THRESHOLD、GET_THRESHOLD，拒绝未知命令和越界值 |
| 待处理寄存器 | 保存 11 位 `pending_threshold` 及请求序号，合法接收后返回 ACCEPTED |
| 活动寄存器 | `active_threshold` 真正接到算法 threshold 输入，GET 只能读取它 |
| 跨时钟域握手 | 数据在握手完成前保持稳定，作为整体传送，确认应用后再把确认事件传回 UART 域 |
| 帧同步更新 | 与阈值比较级帧边界对齐，每帧内保持阈值稳定，不能只看摄像头输入端 SOF |
| 应用确认 | 活动寄存器更新完成后，回传同序号 APPLIED；若更新未发生，不能先回复成功 |
| 忙与故障处理 | 未完成 SET 期间对新 SET 返回 busy；PING 正常响应，GET 返回读取时的活动值且不取消待处理更新。应避免部分更新并定义故障取消或恢复路径；上位机不能从内部故障回复推断活动值未改变 |
| 复位处理 | 定义复位阈值，清除旧请求和缓存；不能把重启前的确认用于重启后的命令 |

若 GPIO 按键或其他控制源也能修改阈值，应明确优先级，并保证 GET 返回最终活动值。V1 没有主动状态广播，上位机必须通过读取获知其他来源的更新。

## 分步验收

### A. 仅验证串口与参数，不接图像

1. 确认串口助手和上位机不会同时占用同一 COM 口。
2. 发送协议中的 PING 示例，收到同序号 PONG。
3. 分两段发送一帧、连续发送多帧、插入噪声、破坏 CRC，确认不会错误执行命令，后续合法帧仍可恢复。
4. 验证阈值 `0`、`1`、`320`、`2047` 可接受，`2048` 及 `65535` 返回 invalid_value；PING/GET 的非零 value 也应被拒绝。
5. 尚未接入算法时，可以用明确标识的“寄存器测试固件”验证 ACCEPTED、应用确认和读回。它证明参数链路成立，不能标记为“图像阈值已生效”。
6. 验证未知命令、错误版本、忙状态和复位路径的正确回复；模拟 ACCEPTED 丢失后内部故障的情况，确认上位机将结果视为未知并要求读回。记录 HEX 收发与固件版本。

### B. 接入图像处理

1. 将活动阈值接入实际使用的 Sobel 核心，核对顶层连接和 11 位位宽。
2. 根据行缓存和流水线延迟生成比较级的帧边界，记录更新发生在哪一个时钟周期。
3. 在帧中途发 SET，先观察 ACCEPTED，确认当前帧始终使用旧阈值；在约定边界更新后再回复 APPLIED。
4. GET 读回与读取时的活动寄存器一致，不能返回暂存值来冒充活动值；GET 不取消待处理更新，读回旧值后旧请求仍可能在后续边界生效。
5. 使用稳定测试图案调整阈值，检查预期边缘变化，并确认无半帧不同阈值造成的画面分界。
6. 覆盖图像暂停、无输入、复位和 UART/图像不同频率的情况；检查忙状态不会无限卡住且没有虚报 APPLIED。

### C. 上位机与实板联合验证

1. 用真实串口模式完成“连接 → PING → GET → SET → ACCEPTED → APPLIED → GET”。
2. 设置等待期间拔线、故意使用错误波特率、占用端口，检查软件保持响应并显示故障，不把通信失败显示为成功。
3. 让 APPLIED 丢失或延迟，确认上位机超时后不自动重发；待设备结束更新后，用新的 GET 读回。
4. 记录实际板卡型号、固件版本、串口参数、操作值、收发日志、活动寄存器或波形证据，以及 HDMI 观察结果。

完成 A 只能说明串口和参数链路可用；完成 B、C 后，才可以声称在对应板卡和固件上完成了图像阈值控制实板验收。

# 新增协议：Sobel Threshold UART V1

**这是本次上位机开发新制定的接口约定，不是原仓库、板商 Demo 或当前开发板已实现的协议。** 本文同时约束上位机和未来的 FPGA 实现。版本号为 `0x01`；阈值沿用算法核心默认的 11 位范围 `0–2047`，不改变现有“梯度幅值大于或等于阈值时输出边缘”的算法行为。

## 1. 串口参数

| 项目 | V1 约定 |
|---|---|
| 建议波特率 | `115200`，双方必须设置相同值；上位机允许选择其他波特率 |
| 数据位 / 校验 / 停止位 | `8 / None / 1`（8N1） |
| 硬件 / 软件流控 | 均关闭 |
| 传输内容 | 原始二进制字节，无 ASCII 编码、换行符或文本结束符 |
| 多字节数字 | 无符号整数，低字节先发（little-endian） |

时钟、引脚、电平、波特率分频误差和串口连接方式由实际板级工程确认。上位机打开串口不等于设备已经实现此协议。

## 2. 固定 10 字节帧

| 字节偏移 | 字节数 | 名称 | 内容 |
|---|---:|---|---|
| 0–1 | 2 | 帧头 | 固定 `A5 5A` |
| 2 | 1 | version | 固定 `01` |
| 3 | 1 | type | 命令或回复类型，见下表 |
| 4–5 | 2 | sequence | 请求序号，`1–65535`，低字节在前 |
| 6–7 | 2 | value | 阈值、错误码，或保留零值，低字节在前 |
| 8–9 | 2 | crc | 对偏移 `2–7` 的 6 字节计算 CRC，结果低字节在前 |

CRC 使用 **CRC-16/CCITT-FALSE**：多项式 `0x1021`，初值 `0xFFFF`，输入输出均不反射，最终异或 `0x0000`。不包含帧头和 CRC 自身。标准校验字符串 `123456789` 的结果应为 `0x29B1`。

接收端必须将串口看作字节流：一次读取可能只有半帧，也可能包含多帧，不能假定一次读取等于一条回复。寻找帧头后等待满 10 字节并检查 CRC；CRC 错误时从候选帧头后一个字节继续搜寻，丢弃坏帧并重新同步。没有完整帧时保留需要的尾部字节；缓存必须有上限。CRC 错误、噪声以及序号为零的帧不执行命令，也不回复，避免对损坏的命令进行猜测。

## 3. 命令和回复

所有回复必须回显触发请求的 `sequence`。上位机按序号与预期类型匹配，忽略过期序号或与当前操作不相符的回复，并在日志中留痕。

| 方向 | 类型名 | type | value | 含义 |
|---|---|---:|---|---|
| 电脑 → FPGA | PING | `01` | 必须为 `0` | 检查对端是否理解 V1 |
| 电脑 → FPGA | SET_THRESHOLD | `02` | `0–2047` | 请求更新阈值 |
| 电脑 → FPGA | GET_THRESHOLD | `03` | 必须为 `0` | 请求当前实际生效阈值 |
| FPGA → 电脑 | PONG | `81` | 必须为 `0` | 对 PING 的回复；帧内 version 标识版本 |
| FPGA → 电脑 | ACCEPTED | `82` | 接受暂存的阈值 | SET 已校验并暂存，尚不代表生效 |
| FPGA → 电脑 | APPLIED | `83` | 实际生效的阈值 | SET 的值已进入图像处理活动寄存器 |
| FPGA → 电脑 | THRESHOLD | `84` | 当前实际生效阈值 | 对 GET 的回复，不可返回尚未生效的暂存值 |
| FPGA → 电脑 | ERROR | `FF` | 错误码 | 当前请求失败，见下表 |

SET 的正常顺序为 `ACCEPTED` 后 `APPLIED`，两者使用相同序号和目标阈值；可以紧接着发出，FPGA 应发送这两个阶段的回复。若 ACCEPTED 在链路上丢失，但 APPLIED 在当前 SET 等待期限内到达且序号、阈值均匹配，上位机仍可确认生效，因为 APPLIED 提供了更强的完成证据。FPGA 不主动发送不属于某次请求的状态帧，V1 也不使用序号零广播。

| 错误码 | 名称 | 何时回复 |
|---:|---|---|
| `1` | unsupported_version | CRC 正确但 version 不是 `01`；ERROR 回复本身使用 version `01` |
| `2` | unknown_command | 不认识的请求 type |
| `3` | invalid_value | 阈值越界，或者 PING / GET 的 value 非零 |
| `4` | busy | 上一条阈值更新尚未完成，当前请求不能安全处理 |
| `5` | internal_failure | 无法完成所请求的操作，且不能给出成功确认 |

FPGA 应在接受 SET 前完成版本、命令、参数和忙状态检查，以错误码 `1–4` 拒绝未接受的请求，并保持该次请求不改变活动值。只有在上位机尚未观察到 ACCEPTED 且收到这些明确拒绝码时，才保留之前的确认值；它仍是历史快照，不是新的读回。

**没有收到 ACCEPTED 不等于设备没有接受 SET，因为这条回执可能丢失。** SET 收到 `internal_failure`（`5`）或未知错误码时，无论之前是否看到 ACCEPTED，应用结果均视为未知：清除活动值显示并要求 GET 读回。上位机已经看到 ACCEPTED 后再收到任何 ERROR，也按结果未知处理。ERROR `5` 不保证旧值保持不变，不能从错误回复反推该次更新没有发生。FPGA 应避免部分更新，定义故障取消或恢复路径，并使用同一序号报告失败；上位机仍须依据读回恢复对当前值的认识。

## 4. 已发送、已接受、已生效

```text
电脑发送 SET(640)                 电脑显示：命令已发送
FPGA 检查参数并保存 pending=640
FPGA 回复 ACCEPTED(640)           电脑显示：设备已接受，等待生效
FPGA 在正确的算法帧边界更新 active=640
FPGA 回复 APPLIED(640)            电脑显示：参数已生效
电脑发送 GET
FPGA 回复 THRESHOLD(active)       电脑显示：当前活动值
```

`pending_threshold` 是等待使用的新值，`active_threshold` 是实际驱动算法 `threshold` 输入的值。它们必须分开。不能在 UART 收到命令时直接回复 APPLIED，也不能用尚未生效的值回答 GET。

已有算法包含行缓存和流水线。生效边界应与**阈值比较级实际处理的帧边界**对齐，不可简单使用摄像头输入端的新帧信号，否则旧帧尾部仍可能使用新阈值。阈值跨时钟域时采用原子握手，不能逐位独立同步这 11 位数值。暂停或尚未开始的图像流水线也需要明确的更新策略；如果不能证明已应用，保持待处理状态并让上位机超时，不能虚报生效。

## 5. 序号、等待和恢复规则

- 同一时刻只允许一条业务请求等待回复。上位机在一次应用运行期间使用递增序号 `1–65535`，包括断开再连接也不复用；序号用尽后要求重启应用。重新连接后清空本地解析缓存和失效请求，避免把残留回复当作新命令结果。重新启动应用会开启新的序号空间，实板应清理旧会话积压回复，并先完成连接检查和读回。
- 串口连接建立后，上位机自动发送 PING；匹配的 PONG 到达后，自动发送 GET。只有连接检查确认设备支持 V1，才允许进行阈值操作。每次手动检查连接也会先撤销此前的协议确认，匹配 PONG 到达后恢复确认并重新读回阈值。检查超时后，阈值操作保持禁用，直到检查重新成功。
- PING、GET 和 SET 的首个有效回复等待时间为 **1 秒**。SET 收到 ACCEPTED 后，再等待 APPLIED 最多 **2 秒**；重复 ACCEPTED 不能无限延长该等待。
- 无自动重试，尤其是 SET。超时、断线或响应损坏时，不能推断命令是否被执行；界面保留“未确认”或“未知”的含义。
- SET 超时后，用户先执行 GET 获取实际值。GET 始终返回设备处理读取请求时的活动值，即使此前仍有待处理 SET；GET 不取消待处理更新。一次读回只确认该时刻的值，不能证明上一条 SET 成功或失败，旧请求之后仍可能生效。若仍有未完成的设置，FPGA 对新的 SET 返回 busy；PING、GET 可正常响应。
- 对于超时后迟到的 APPLIED，上位机不得把它当作当前请求的成功；新的 GET 使用新序号。
- 超时不意味着 FPGA 自动取消。FPGA 必须自行定义待处理更新的可完成条件和故障取消路径，不能依赖上位机超时来清掉寄存器。该行为应在实板接口验收记录中说明。
- 串口写入未完成、串口读写异常、拔线均是通信故障，不得显示为设备接受或已生效。

## 6. HEX 例子

以下为空格分隔的原始字节，空格只是便于阅读。可在支持 HEX 发送的串口助手中发送；不要使用 ASCII 文本模式发送这些字符。例子 CRC 已用独立的标准 CRC 计算校验。

| 操作 | 完整 10 字节 |
|---|---|
| PING，序号 1 | `A5 5A 01 01 01 00 00 00 55 97` |
| PONG，序号 1 | `A5 5A 01 81 01 00 00 00 85 B5` |
| SET 320，序号 2 | `A5 5A 01 02 02 00 40 01 B6 FF` |
| ACCEPTED 320，序号 2 | `A5 5A 01 82 02 00 40 01 66 DD` |
| APPLIED 320，序号 2 | `A5 5A 01 83 02 00 40 01 37 77` |
| GET，序号 3 | `A5 5A 01 03 03 00 00 00 BE 3E` |
| THRESHOLD 320，序号 3 | `A5 5A 01 84 03 00 40 01 57 66` |
| ERROR invalid_value，序号 4 | `A5 5A 01 FF 04 00 03 00 BD 8E` |

这里 `320 = 0x0140`，所以 value 两字节按 `40 01` 发送。阈值上限 `2047 = 0x07FF`，按 `FF 07` 发送。CRC 自身也使用低字节先发，算法移位方向与线路字节序是两件事。

## 7. 模拟模式与验证边界

模拟器初始活动值为 `320`，正常 SET 先回复 ACCEPTED，约 150 毫秒后回复 APPLIED。可切换为不响应、拒绝 SET、接受但不生效等故障模式。“拒绝设置”场景返回 internal_failure（`5`），上位机必须先显示当前值未知；重新 GET 才能确认模拟器仍保持原活动值 `320`。该场景中的旧值不变是模拟器行为，不能推广为所有内部故障都没有副作用。该延时只用于显示操作阶段，不是硬件时序要求。模拟器用于测试上位机状态和协议处理，不替代 UART 电气、时钟域、帧边界或图像效果的实板验证。

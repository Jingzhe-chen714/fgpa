# Sobel 阈值串口上位机

这是运行在 Windows 电脑上的第一版控制面板，用于检查 FPGA 的串口通信、设置 Sobel 阈值，并读取当前已经生效的阈值。窗口使用 PySide6，串口通信使用 pySerial。

**当前协议是本次新增的 V1 设计。原仓库没有实现对应的 FPGA UART 命令解析。模拟模式可以直接体验；真实开发板必须先实现 [FPGA 接口清单](FPGA_INTERFACE_CHECKLIST.md) 才能响应。本软件没有修改现有图像算法。**

## 第一次启动：先用模拟模式

1. 确认电脑已安装 Python 3.10 或更高版本，推荐 Python 3.11 或 3.12。没有安装时，可从 [Python 官方网站](https://www.python.org/downloads/windows/) 安装，并启用 Python launcher 或加入 PATH。Efinity 自带的内部 Python 不作为本程序运行环境。
2. 在资源管理器中打开这个 `host_app` 文件夹，双击 `setup.bat`。它在本文件夹建立 `.venv` 并安装依赖；首次安装需要联网，无需管理员权限。看到 `Setup complete` 表示完成。安装失败时窗口会保留错误信息。
3. 双击 `start_simulation.bat`。窗口会明确显示模拟模式并自动连接，所有设备响应来自电脑内部的模拟器。
4. 建立模拟连接后，软件会自动检查连接并读取阈值。将输入值改为 `640` 并设置，观察“已发送 → 设备已接受 → 参数已生效”，随后手动读取应返回 `640`。也可随时手动检查连接。
5. 关闭软件即可。下次直接双击启动脚本，无需重复安装依赖。

`start.bat` 打开真实串口模式，初始为未连接状态；`start_simulation.bat` 打开模拟模式。启动脚本会自动进入正确文件夹，路径含中文或空格也可以使用。模拟初始阈值为 `320`，它只是演示设定，不代表开发板复位值。

## 三个状态必须分清

| 界面状态 | 能证明什么 | 还不能证明什么 |
|---|---|---|
| 命令已发送 | 电脑完成向通信通道写入本条命令 | FPGA 已收到、已接受或已生效 |
| 设备已接受 | 收到 `ACCEPTED`，设备已经校验并暂存目标值 | 图像处理当前正在使用该值 |
| 参数已生效 | 收到 `APPLIED`，设备确认算法正在使用该值 | 摄像头、HDMI 和图像效果已经通过实板验收 |
| 读取当前阈值 | 收到 `THRESHOLD`，设备报告当前活动寄存器值 | 在没有实板证据时，不能证明实际电路实现符合约定 |

设置等待过程中，之前读到的数字标记为“上次确认的有效阈值”，不能当作新设置结果。若 ACCEPTED 丢失但及时收到序号和数值均匹配的 APPLIED，仍可确认生效。设置超时后当前值显示未知，必须重新读取；新的读回证明读取时的活动值，不会倒推上一条设置一定成功。

超时后软件不自动重发设置命令，因为设备可能已经执行，只是响应丢失。此时先读取当前阈值。读取不会取消待处理设置，读到旧值也不等于前一条设置永远不会生效；如果随后设置新值时设备报告忙，应等待待处理更新完成或排查 FPGA 的帧时钟，再重新读取。

设备返回内部故障或未知错误时，设置结果也会显示未知，即使没有看到“已接受”也一样，因为接受回执可能丢失。重新读取才能确认当前值。只有在未看到接受回执时收到明确的版本、命令、参数或忙状态拒绝，软件才保留之前的确认快照；已经接受后再收到任何错误，都要重新读回。

## 界面里的功能

- 选择真实串口或明确标注的模拟模式，刷新端口，选择波特率，连接和断开。
- 检查连接、输入 `0–2047` 的阈值、设置阈值、读取当前活动阈值。
- 显示命令状态，以及带时间的收发日志；字节可选 HEX 或 ASCII 转义显示，支持导出 CSV，界面保留最近 1000 条记录。
- 模拟正常响应、完全不响应、拒绝设置，以及已接受但不生效，用于检查失败处理。

此版使用固定二进制协议进行业务操作，不发送文字 `640` 来代表阈值。协议和完整 HEX 示例见 [PROTOCOL_V1.md](PROTOCOL_V1.md)。同一时刻只允许一条业务命令等待响应，避免返回值混淆。

切换模拟场景前先断开连接，选好场景后重新连接。每次新建模拟连接会回到初始值 `320`；真实 FPGA 的断开连接不一定会复位，不能据此推断实际设备行为。

| 模拟场景 | 可以观察的行为 |
|---|---|
| 正常响应 | 设置后依次显示接受和生效，再读回新值 |
| 无响应 | 自动检查连接超时，不能把端口打开当成协议连接成功 |
| 拒绝设置 | 设置返回内部故障，界面先显示当前值未知；重新读取后才确认模拟器仍保持原值 `320` |
| 接受但不生效 | 先显示已接受，约 2 秒后生效等待超时；读回仍为原值，继续设置会因旧更新待处理而报告忙 |

## 连接真实开发板

先让负责 FPGA 的同学完成 [接口清单](FPGA_INTERFACE_CHECKLIST.md)，并给出实际板卡型号、UART RX/TX 引脚、时钟和复位条件、波特率、固件版本及复位阈值。默认 `115200` 只是本次新协议建议值，不是从现有工程测得的参数。

1. 将实现了 V1 协议的 FPGA 工程编译下载到开发板，连接开发板的串口接口。在 Windows 设备管理器中确认实际 COM 端口。
2. 关闭会占用同一端口的串口助手。双击 `start.bat`，选择真实端口与双方一致的波特率。串口格式固定为 8 个数据位、无校验、1 个停止位（8N1），无流控。
3. 点击连接，软件会自动检查连接并读取当前阈值。端口打开只表示电脑能访问它，收到 `PONG` 才表示另一端理解本协议。
4. 记录读回的当前阈值。然后设置一个与原值不同的数，等待 `ACCEPTED`、`APPLIED`，再读回确认一致。
5. 恢复原阈值。接入图像系统后，用稳定画面比较不同阈值下的边缘效果，并保存软件日志和实板观察记录。

拔线、端口被占用、错误波特率或旧固件只会造成错误或超时，不能当作“设备已接受”。检查连接失败时，优先核对串口端口、双方波特率、下载的固件和 UART 引脚；JTAG 下载口与串口口可能不同。

每次点击“检查连接”都会重新验证对端；如果超时，阈值操作会保持禁用，直到检查成功。以前成功连接过不代表这一次检查也成功。

## 用命令行启动和测试

在 `host_app` 目录打开 PowerShell：

```powershell
# 第一次安装（之后直接启动即可）
.\setup.bat

# 模拟设备
.\start_simulation.bat

# 真实串口模式，启动时未连接
.\start.bat

# 等价的 Python 入口
.\.venv\Scripts\python.exe -m sobel_host --simulate

# 运行软件自动化测试
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

测试结果应分三类记录：协议和软件测试、模拟设备联调、真实开发板联调。前两类通过不能代替第三类。没有连接真实开发板时，实际引脚、电气连接、串口时序、CDC 和图像阈值效果都仍待验收。

## 常见问题

| 情况 | 处理方法 |
|---|---|
| 提示找不到 Python | 安装推荐版本并启用 launcher 或 PATH，再运行 `setup.bat` |
| 依赖下载失败 | 检查网络及窗口内错误信息，恢复后重跑 `setup.bat` |
| 提示 `.venv` 不可用 | 关闭程序，将本目录的 `.venv` 改名留存，再运行 `setup.bat` |
| 端口列表为空 | 检查开发板串口连接及驱动，在设备管理器确认 COM 口；模拟模式不需要 COM 口 |
| 端口打开失败 | 关闭其他串口程序，确认设备未拔出，重新刷新端口 |
| 端口打开成功但检查连接超时 | 核对双方串口参数和新协议固件。原 UART 回显示例不一定支持本协议 |
| 已接受但一直不生效 | 检查 FPGA 图像帧是否运行、比较级帧边界条件、CDC 握手和返回路径 |
| 发送超时或设置生效超时 | 不猜测当前值，不盲目重发；先读取状态，必要时排查待处理更新 |

软件只控制阈值，不承担实时视频传输、FPGA 编译下载或板卡引脚配置。依赖安装方式参照 [Qt for Python 官方文档](https://doc.qt.io/qtforpython-6/gettingstarted.html) 和 [pySerial 官方文档](https://pyserial.readthedocs.io/en/latest/pyserial.html)。

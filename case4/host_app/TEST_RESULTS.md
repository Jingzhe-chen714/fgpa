# 上位机第一版验证记录

验证日期：2026 年 10 月 2 日。基线仓库提交：`a5cdf92`。本记录对应新增 `case4/host_app` 的本地实现。

## 已实际完成的软件验证

运行环境：Windows，Python 3.11.9，PySide6 6.11.2，pySerial 3.5；依赖安装在本应用的 `.venv`，依赖一致性检查通过。

| 检查 | 实际结果 |
|---|---|
| 协议编码、CRC、分批与合并接收、噪声重同步 | 9 项通过 |
| 模拟设备和模拟串口驱动故障 | 15 项通过 |
| 命令状态、序号、超时、断线与恢复 | 32 项通过 |
| Qt 界面按钮操作与模拟故障提示 | 3 项通过 |
| 上位机测试合计 | **59 项全部通过** |
| 原仓库 Python Golden 算法自检 | **7 项全部通过** |
| Windows 安装脚本与模拟启动脚本 | 执行成功 |
| Windows 原生窗口 | 已启动并检查中文字体、布局和模拟标识 |
| 用户操作录屏（模拟模式） | 启动后初值 320，设置 640 后确认接受与生效，读取返回 640 |
| 已有算法文件差异检查 | 原有 RTL、测试平台、Golden 模型及原依赖文件无修改 |

上位机测试复现命令，在本目录的 PowerShell 中运行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m pip check
```

GUI 自动化测试使用 Qt 的 offscreen 平台，全部通信对象为模拟设备；另行使用 Windows 原生窗口检查了实际显示与启动脚本。真实串口错误用驱动替身注入，不能把这些测试称为实体 USB 拔线测试。

提交 PR 前重新执行了全部 59 项上位机测试、依赖一致性检查，以及原仓库 7 项 Golden 自检，均通过。Golden 自检使用已安装原算法依赖的独立 Python 环境；上位机 `.venv` 只安装界面与串口依赖，不包含 NumPy 等算法测试依赖。

用户录屏中的模拟启动、设置 640、回读 640 流程已通过画面检查。录屏未展示真实开发板通信、断开、日志导出或故障场景，也未用于验证这些操作；录屏及抽帧不纳入仓库。

关键验证包括：ACCEPTED 不改变上次确认阈值；匹配 APPLIED 才确认设置生效；丢失 ACCEPTED 但收到匹配 APPLIED 时仍可确认；内部故障即使没有观察到 ACCEPTED，也不能推断原值保持不变；响应或生效超时不自动重发 SET；迟到回复不完成其他序号的请求；GET 仅确认读取时的活动值。

## 2 总体架构与数据流

### 2.1 算法核心边界与像素流接口

当前工程以算法像素流为实现边界，输入是已完成像素拼接和坐标标记的 RGB 数据，输出是与图像中心坐标对应的梯度、幅值及二值边缘判定。[基础核心](D:/contest/2026FPGA/yilingsi/case4/rtl/case4_gray_sobel_core.sv)和[中值级联核心](D:/contest/2026FPGA/yilingsi/case4/rtl/case4_gray_median_sobel_core.sv)分别实现不带中值滤波、带中值滤波的两条处理链；两者尚未接入摄像头协议、显示时序或板载交互模块。二者的实现范围止于同步算法像素流，采集、显示与控制层则构成待建系统的外部边界。[4]

两条核心共用 24 位 `in_pixel` 输入端口，通过参数 `PIXEL_FORMAT` 选择 RGB565 或 RGB888。RGB565 使用低 16 位，RGB888 使用全部 24 位；前端将颜色分量解包并生成 8 位灰度，使后续窗口与空间运算使用统一的数据宽度。每个像素同时携带 `in_valid`、`in_x`、`in_y`、`in_sof`、`in_eol` 和 `in_eof`，其中坐标是有效图像区域内从零开始的位置，三个标记分别与帧首、行末和帧末的有效像素同行。灰度前端在登记像素的同时登记这些侧带信息，后续运算据此保持像素值和空间位置的一致性。[4]

输入必须按逐行扫描顺序提供完整有效像素，但时间上允许存在 `in_valid=0` 的空拍。空拍表示该时钟没有新像素，不代表像素值为零，也不使行内坐标自动前进。正常运行时，核心在 `in_valid=1` 的上升沿接收当前像素；端口没有 `ready`，因而不存在由下游暂停上游的反压机制。外部适配逻辑需要自行保证像素顺序、坐标和标记一致，并保证下游能够接收结果。窗口会利用行末坐标进行行结束判断，但这不构成对缺失像素、乱序输入或任意视频协议的自动修复。[4]

### 2.2 基础 Sobel 处理链

基础路径的数据流为 RGB565/RGB888 输入 → 定点灰度 → 3×3 灰度窗口 → Sobel 梯度与幅值 → 阈值判定。灰度模块每次输出一个像素，窗口模块则将当前像素与历史行、历史列中的像素组合为九点邻域。Sobel 接收的是完整空间窗口，而不是九个连续到达的一维像素；窗口中心坐标随九点数据一同进入运算流水线，使输出位置不再等同于此时正在输入的最新像素位置。[4]

窗口采用 `VALID_ONLY` 边界策略，只在邻域全部位于原图内部时发出有效结果。当灰度流到达位置 `(2,2)` 时，才具备以 `(1,1)` 为中心的第一个完整窗口。对于宽为 W、高为 H 的正常图像，基础核心的有效输出中心为横坐标 1 至 W−2、纵坐标 1 至 H−2，对应 `(W−2)×(H−2)` 个结果。输出帧首标记随第一个有效窗口重新产生，输出行末、帧末标记对应裁去边界后的有效结果序列，不能直接当作完整 W×H 显示光栅的同步信号。[4]

Sobel 输出经过阈值级后，核心同时提供 `out_gx`、`out_gy`、`out_magnitude` 和 `out_edge`，并保留结果坐标和行帧标记。阈值级使用当前控制端口 `threshold` 对幅值作判定，核心也对梯度路径作寄存对齐，使这些量对应同一笔像素事务。算子接口保留了传输有效 `out_valid` 与窗口有效 `out_win_valid` 两种资格信号；在这两条集成核心中，Sobel 的输入有效和窗口有效均由各自末级窗口的有效信号驱动，因此实际只传递完整邻域的结果，并未保留无效边框的像素事务。[4]

### 2.3 中值滤波后的 Sobel 处理链

中值路径的数据流为 RGB 输入 → 灰度 → 第一组 3×3 窗口 → 中值像素 → 坐标重基 → 第二组 3×3 窗口 → Sobel → 阈值判定。第一组窗口围绕原始灰度图建立邻域，中值算子把九个灰度值归约为一个输出像素。这个输出像素只是中值图中的一个采样点，不能代替 Sobel 所需的九个相邻中值像素，因此中值后仍需独立的第二组窗口。两级运算不能通过共享同一个原始灰度窗口直接串接。[4]

第一组窗口和中值算子输出的中心坐标仍处于原图坐标系，即从 `(1,1)` 开始，形成宽 W−2、高 H−2 的中值图。第二组窗口要求其输入坐标从零开始，核心在 `med_valid` 有效时将 `med_x`、`med_y` 分别减一，并把第二组窗口的尺寸设为 W−2、H−2。该重基只改变坐标表达，不压缩时间轴，也不消除第一组窗口预热和行首无效区域造成的空拍。第二组窗口仍按有效事务更新历史样本，因此空间上连续的中值图可以通过带空拍的流式接口传递。[4]

第二组窗口得到的是中值图局部坐标，其中心在进入 Sobel 前再加一，恢复到原图坐标系。两次 3×3 邻域运算级联后，完整结果所依赖的原始图像范围扩展到 5×5，最终有效中心为横坐标 2 至 W−3、纵坐标 2 至 H−3，有效输出规模缩小为 `(W−4)×(H−4)`。这种区域收缩与中值算法的排序实现无关，而由连续两级完整邻域的要求决定。[Golden 模型](D:/contest/2026FPGA/yilingsi/case4/golden_edge.py)相应使用半径为 1 或 2 的有效掩码描述两条路径的可比较区域；软件保存的完整尺寸数组与硬件只发出内部有效像素的流式输出，应通过坐标和有效区域建立对应关系。[3][4]

### 2.4 窗口存储与时序含义

空间邻域决定了系统存在行级等待。基础窗口必须先收到足够的历史行和列，中值支路的第二组窗口还必须等待中值图自身的历史行积累完成。在窗口具备有效邻域后，灰度、中值、Sobel 和阈值等寄存级继续引入时钟级延迟。因此，流水线结构所支持的稳态每拍接收一个有效像素，与输入像素立即产生输出是两个不同概念；行首、帧首预热以及输入空拍也会使结果流出现无效周期。每拍处理能力仅描述设计吞吐，不能代替端到端延迟分析，也不能直接推导板级最高频率或显示帧率。[4]

两个核心均通过 `WINDOW_BACKEND` 选择窗口实现：参数为 0 时采用数组参考路径，为 1 时采用 Xilinx BRAM 路径。两者保持窗口内容、中心坐标和有效区域的契约，但内部存储组织与读出时序不同。当前 [Xilinx 窗口实现](D:/contest/2026FPGA/yilingsi/case4/rtl/window3x3_gray_xilinx_bram.sv)使用两个物理行缓存轮换历史行角色，同步读取需要同时延迟像素、坐标和行帧标记；中值支路实例化两组这样的窗口，第二组按缩小后的图像宽度缓存中值行。[4]

存储后端的可替换性依赖时序语义保持一致，而不仅是端口名称一致。当前 Xilinx 路径依赖一拍同步读和同地址读写返回旧值的 `READ_FIRST` 行为，相关约定记录于 [BRAM 迁移说明](D:/contest/2026FPGA/yilingsi/case4/BRAM_PORTABILITY.md)。目标 Ti60 的 RAM/IP 配置与对应时序验证尚未落实，不能把现有 XPM 分支作为目标平台适配完成的证据。后续若目标 RAM 的读延迟不同，窗口数据和全部侧带信息必须共同调整。[7]

### 2.5 拟建采集与显示系统

拟建整机将在算法核心之前完成摄像头配置、总线采集、像素拼接和有效坐标生成，再按照实际时钟关系接入跨时钟域缓冲。该前端的职责是把器件相关的传感器接口转化为本章定义的有序像素流；算法核心内部不承担摄像头寄存器配置，也没有处理不同输入时钟的逻辑。摄像头型号、接口电气连接、采样时钟、跨时钟域方案和目标工程约束均属于待完成的板级集成内容。

显示侧需要把内部有效结果重新映射到完整显示画面，并为被裁去的边界建立明确处理规则。当前两条核心没有保留原始 RGB 旁路，内部传入 Sobel、阈值算子的 RGB 端口接零，因而不能仅凭现有核心输出完成原图与边缘的彩色叠加。后续需要另行保存或延迟原图数据，按同帧、同坐标与边缘结果对齐，再组织原图、灰度、边缘或叠加画面的显示。已有叠加算子只承担对齐后像素的颜色替换，不等于原图对齐、完整边框与显示时序已经集成。[4]

阈值按键或其他交互输入还需经过同步和控制逻辑，明确参数在帧内或帧间生效的规则；是否使用 DDR 帧缓存，则需结合采集与显示速率、时钟关系及画面组织方式确定。现有算法核心尚未包括上述外部功能。【待完成：目标板与摄像头、显示接口的连接关系，原图及灰度旁路对齐方案，完整边界映射，跨时钟域与帧缓存方案，阈值交互控制及系统顶层集成。】

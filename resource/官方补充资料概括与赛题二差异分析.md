# 官方补充资料概括与赛题二差异分析

分析日期：2026-08-30；RTL与验证同步：2026-08-30至2026-08-31

本文同时保存官方资料分析和本轮实现记录；第5节为调整后的状态，第13节为具体改动、回归和剩余边界。

## 1. 结论摘要

新版《2026 FPGA竞赛赛题指南 -8.22(更正版)》中的赛题二与最初 PDF **核心功能一致，但平台接口要求并非完全一致**。更正版把旧版允许选择的实现明确收敛为：

- 总线：由“如 AXI4 / Wishbone”收敛为 **AXI4**；
- 外存：由“DDR / SDRAM”收敛为 **DDR3**；
- 显示：由“VGA / HDMI”收敛为 **HDMI**；
- Burst/FIFO：旧版要求“合理使用”，更正版直接要求“使用”，应按基础必做处理。

因此，当前 Case 2 RTL **不需要推倒重写渲染功能核**，但也不能概括成“只差接总线和 CPU”而完全不改内部数据通路。应保留命令格式、解析器、Fill/Copy/Alpha/Color-Key、owner 仲裁、行级写 burst、双缓冲和视频光栅；同时完成以下针对性重调：

1. 新增 AXI4-Lite CSR/命令从接口和 AXI4 Full 内存适配器（本轮 RTL 已完成，真实 IP 端口对接待完成）；
2. 将渲染器的源图/背景图读取由单 beat 改为行级 burst，复用同步行缓存（本轮已完成）；
3. 接入 DDR3 controller/PHY、校准、位宽转换、CDC 和错误响应；
4. 接入 640×480@60 的实际像素时钟和 HDMI TX/桥接、引脚及时序约束；
5. 编写 RISC-V 驱动、双缓冲软件流程、CPU/硬件 FPS 对比 Demo；
6. 若冲击高阶得分，将 Alpha 改为固定位宽流水 DSP 路径并完成 60 FPS Sprite 实测。

当前状态应准确表述为：**板卡无关 2D 渲染协处理器、AXI4 接口层和行级读写 burst 已完成本轮 RTL 调整与自检；真实 Sapphire/DDR3/HDMI、跨时钟 IP、软件 Demo 和板级性能闭环尚未完成。**

## 3. 更正版指南概括

### 3.1 平台与规则

- PDF 第7页：赛题一至三使用 Ti60F225I3 平台，板上提供 MIPI CSI-2、HDMI、DDR3 和千兆以太网等接口。
- PDF 第8页：赛题四采用另一款 Ti60F225 开发板，接口侧重 HDMI、LVDS、DVP 和 MIPI RX/TX。
- PDF 第27页：官方支持资料包括 Efinity、Ti60 文档、Sapphire RISC-V、MIPI、DDR 控制器和 HDMI/VGA 参考设计；其中部分资源在竞赛群提供。
- PDF 第29页 Q&A：赛题一至四要求使用 Ti60 芯片，但不强制必须使用指定开发板；第三方板卡获得的官方技术支持会更少。

第7页“集成 RISC-V 处理器及专用 NPU”的宣传性表述不应直接理解成当前 Case 2 已经拥有可直接连线的硬核 CPU/NPU。赛题二仍需在 Efinity IP Manager 中生成并配置 Sapphire SoC；NPU也不是赛题二要求。

### 3.2 四个赛题

- 赛题一（第10–13页）：MIPI 摄像头输入、轻量风格迁移网络硬件加速、DDR 帧缓存、HDMI 输出和 RISC-V 调度；基础目标是640×480下达到15 fps，高阶目标包含多风格、高分辨率和网络轻量化。
- 赛题二（第14–17页）：RISC-V 运行游戏/GUI，AXI4 挂载 BitBlt 引擎，通过 DDR3 framebuffer 和 HDMI 形成显示闭环；基础算子为 Block Copy 和 Solid Fill，高阶为 Alpha、Color Key 和高负载 Sprite Demo。
- 赛题三（第18–22页）：视觉、红外温度和环境传感融合，使用 RISC-V/TinyML 和 FPGA 加速实现本地多模态感知。
- 赛题四（第23–26页）：摄像头采集、灰度、中值滤波、Sobel、HDMI/VGA 显示；高阶包含 DDR 帧缓存、Canny、彩色边缘叠加和简单形状识别。

## 4. 赛题二新旧版本逐条比较

### 4.1 总体判断

旧版赛题二位于 PDF 第7–9页，更正版位于 PDF 第14–17页。Block Copy、Solid Fill、指令字段、640×480@60、双缓冲、CPU/硬件 FPS 对比、Alpha、Color Key 和高负载 Demo 均被保留；变化主要是接口选择收窄和展示重点加强。

## 6. 是否需要重调当前 RTL

### 6.1 可以直接保留

- 256-bit command ABI、FIFO和命令解析；
- Solid Fill、Block Copy、Alpha、Color Key 的像素语义；
- 带 owner 的两主仲裁和延迟 `wr_rsp` 契约；
- 行级写 burst、最大 burst/4 KiB拆分；
- 显示 burst reader、line FIFO、vblank page flip和首帧安全策略；
- 640×480标准光栅参数；
- 行为模型和现有 XSIM 自检作为板卡无关参考。

### 6.2 P0 重调/集成及本轮完成范围

1. **AXI4控制接口：本轮 RTL 已完成**
   - 增加 Sapphire 到加速器的 AXI4/AXI4-Lite寄存器从接口；
   - 正确处理AW/W独立握手、WSTRB、B响应、AR/R和背压；
   - 适配到现有 `csr_valid/write/addr/wdata/rdata/ready`，或直接扩展CSR层。

2. **AXI4 DDR3数据接口：本轮 adapter RTL 已完成，DDR3 IP 尚未接入**
   - 将当前抽象descriptor/数据/响应映射到AXI4 AW/W/B/AR/R；
   - 保持owner到B响应完成，现有`wr_rsp`正好对应AXI B；
   - 按DDR3 IP的64/128位等用户侧宽度打包/拆包RGB565；
   - 保证INCR burst、不跨4 KiB、WSTRB、错误响应和背压正确。

3. **渲染读侧行级 burst：本轮已完成**
   - Copy：源行 burst → 读FIFO/行缓存 → 写burst；
   - Alpha：前景行burst + 背景行burst → 同步读取源行/混合/覆盖同一行 RAM → 写burst；
   - Color Key：完整源行与背景行burst，按透明情况选择结果，连续整行回写；按写掩码节省带宽暂未实施；
   - 不再为每个像素单独发送读descriptor。

4. **DDR3/时钟/CDC/HDMI：仍待真实 IP/板级集成**
   - 生成DDR3 controller/PHY，先完成校准与固定图案读写；
   - 生成系统、DDR、像素时钟和复位释放；
   - 实现display memory CDC和page CDC；
   - 连接HDMI TX或板载HDMI桥，完成RGB格式、DE/HS/VS延迟和引脚/SDC。

5. **RISC-V软件和演示：仍待实现**
   - 命令构造、提交、完成轮询/中断、错误读取；
   - 渲染inactive page → 等待命令完成 → vblank翻页；
   - CPU参考Fill/Copy与硬件路径使用同一场景；
   - 在屏幕上同时显示CPU FPS和FPGA FPS，而不只通过串口打印。

### 6.3 高阶 P1/P2 优化

- 把Alpha从32位`integer`组合表达改为固定位宽、流水化、可选择Efinity DSP primitive的模块，并保留XSIM行为模型；
- 根据实测增加FIFO深度、burst长度、显示优先级和多行预取；
- 增加完成中断、cycle/latency/frame计数器、批量命令或DDR命令ring；
- Custom Instruction只作为可选快速doorbell/状态查询，不替代AXI4寄存器和DDR数据通路；
- 通过实际Sprite尺寸、数量和Alpha/Color Key组合记录稳定60 FPS的上限。

最终判断：这是**中等规模、边界清晰的重调**，而不是从零重写。本轮已补上接口与读 burst；后续工作量主要在真实 DDR3 效率、CDC、HDMI 和软硬件演示闭环。

## 7. EVSOC TinyML 用户手册概括

### 7.1 架构内容

- PDF第6–7页：Edge Vision SoC采用RISC-V控制、DMA、FIFO、预/后处理、硬件加速器、外部存储器和视频接口的异构框架。
- 第7–8页：Ti60F225示例使用MIPI输入、DMA、HyperRAM、硬件加速和显示；完整参考设计资源约为19,246 FF、28,265 LUT、211个M10K和4个DSP。该数字属于特定旧示例，不能当作本赛题资源预算。
- 第8页：DMA支持direct和scatter-gather模式，可由RISC-V轮询或中断等待完成；文中另有256-bit DDR DMA描述，与HyperRAM示例并不完全统一。
- 第9–10页：Hardware Accelerator使用流式流水结构；wrapper包含输入/输出FIFO、控制逻辑、调试/控制寄存器和AXI4 slave接口，通过DMA完成外存数据搬运。
- 第10–11页：TinyML Accelerator通过Custom Instruction接收CPU参数/命令，以AXI4访问外存，包含卷积、ADD、MAXIMUM、MULT和FC等算子。
- 第11–13页：加入自定义加速器时，应同步修改RTL参数、软件参数、控制接口、DMA传输长度、FIFO宽深/上下溢处理和RISC-V地址定义。Hardware Accelerator的参考DMA流接口是32 bit并支持异步通道。
- 第16–31页：TFLite模型导入、参数生成、RISC-V软件工程导入和调试。
- 第32–36页：INT8训练后量化、校准数据和TensorFlow转换流程。

### 7.2 对赛题二的价值

可直接借鉴的是“AXI寄存器控制 + DMA/AXI数据通路 + 输入输出FIFO + 硬件流水线 + RISC-V固件同步”的包装方式。轮询可作为第一版，中断和scatter-gather可作为后续优化。

不能照搬的是HyperRAM、MIPI/DSI和TinyML模型流程。更正版赛题二已经明确DDR3与HDMI；手册中的32/128/256-bit也只是不同示例宽度，不是本赛题固定值。

## 8. RISC-V Custom Instruction资料概括

### 8.1 接口

PDF第3–6页给出独立Custom ALU和ready/valid接口：

| 信号 | 相对CPU方向 | 含义 |
|---|---|---|
| `cpun_customInstruction_cmd_valid` | 输出 | 命令和rs1/rs2有效 |
| `cpun_customInstruction_cmd_ready` | 输入 | 自定义逻辑可以接收 |
| `cpun_customInstruction_function_id[9:0]` | 输出 | 10-bit功能编号 |
| `cpun_customInstruction_inputs_0[31:0]` | 输出 | rs1 |
| `cpun_customInstruction_inputs_1[31:0]` | 输出 | rs2 |
| `cpun_customInstruction_rsp_valid` | 输入 | 结果有效 |
| `cpun_customInstruction_rsp_ready` | 输出 | CPU可接收结果 |
| `cpun_customInstruction_outputs_0[31:0]` | 输入 | 32-bit结果 |

软件侧使用 `opcode_R(opcode, func3, func7, rs1, rs2)` 一类宏调用；命令与结果都必须严格按valid/ready握手并在等待期间保持payload稳定。

### 8.2 对赛题二的判断

一条Case 2命令至少需要op、src、dst、width、height，现有完整ABI为256 bit，而一次CI只有两个32-bit输入和一个32-bit结果。因此CI不适合作为唯一命令接口。

推荐保留AXI4/MMIO命令寄存器和命令FIFO；如需展示RISC-V特色，可增加CI作为`START/DOORBELL`或快速状态读取，让详细描述符仍位于CSR或DDR命令ring。CI不能替代AXI4 DDR burst数据通路。

## 9. Titanium DSP原语资料概括

### 9.1 原语能力

- PDF第2–5页：DSP支持乘、加、减、累加、可变右移、有符号运算、级联和可配置输入/输出寄存器；支持整数及DSP48的BF16模式。
- 提供 `EFX_DSP48`、`EFX_DSP24`、`EFX_DSP12`；DSP48支持多通道，DSP24/12支持小位宽整数。
- PDF第6–8页提供三种原语模板，包含A/B/C、OP、移位、级联、CE、RST和可选pipeline register等参数。
- 多个相同模式的小原语可能被合并到一个物理DSP48，最终占用必须以Efinity报告为准。

### 9.2 对赛题二的判断

Block Copy和Solid Fill不需要DSP。现有 Alpha 的参考舍入语义应保留：

```text
out = (fg * alpha + bg * (255 - alpha) + 128) / 255
```

可先等价改写分子为 `bg * 255 + (fg - bg) * alpha + 128`，使可变乘法减少为每通道一个，并进一步用固定位宽乘加/DSP和常数除法优化。不能直接把 `/255` 换成 `>>8` 后仍声称逐像素等价，特别要检查 alpha=0/255、舍入和饱和。RGB565的5/6-bit通道也适合小位宽并行模式；DSP流水化仍为后续优化，本轮未改变算法数值语义。

当前 `render_cmd_mem_engine` 使用`integer`函数，Efinity结构map将相关乘法拆为partial products并报告0 DSP。这不影响现有功能正确性，也不违反“DSP/硬件乘法器”二选一的字面要求，但会增加LUT与关键路径风险；若准备申报Alpha高阶完成度，应进行器件级DSP重调。

## 10. 建议的赛题二最终系统结构

```text
Sapphire RISC-V
  ├─ AXI4(-Lite) CSR slave ──> command staging/FIFO/parser
  ├─ optional Custom Instruction doorbell ─────────┘
  └─ UART/timer/interrupt ──> driver + FPS/UI

renderer source/background burst reader ──> shared synchronous row RAM
                                          ├─ Fill/Copy/Key/Alpha processing
                                          └─ row burst writer
display burst reader ──> display line FIFO ──> 640x480 timing ──> HDMI

renderer + display owner arbiter
  └─ AXI4 width/burst/response adapter
      └─ DDR3 controller/PHY ──> MT41J128M16 DDR3
```

控制寄存器可以是AXI4-Lite语义，但最终工程应明确属于AXI4体系，并与Sapphire生成接口一致；像素数据必须走AXI4 Full burst。若评审对“AXI4”作严格解释，应在设计文档中清楚说明CSR从接口和DDR主接口分别采用的AXI4子集。

最终审计还完成两项必要修正：

- **AXI AW/W 独立性**：写数据收集及 WVALID 不再等待 AWREADY；允许首拍或全部 W 先于 AW 被接收。`aw_pending_q` 和 `write_data_done_q` 分别跟踪通道进度，两者均完成后才进入 B 等待，避免与等待 WVALID 才拉高 AWREADY 的合法从设备互等。
- **RGB565 每行对齐**：`render_cmd_parser` 与 engine 的直接描述符入口均拒绝使用中的奇数 src/dst stride；parser 返回 `ERR_BAD_STRIDE`。NOP不使用地址/stride，Fill不使用源stride，仍保留这些豁免。该校验避免第一行已写后第二行才出现不对齐错误，也避免边界分段算出零拍。

命令256-bit ABI、op编码、CSR寄存器偏移、owner保持到写完成、已有页翻转语义均未重定义。外存旧黑盒 `c2_ext_mem_adapter_blackbox.sv` 和旧 Sapphire CSR占位仅保留兼容/说明用途，不再代表当前系统的实际 AXI 数据/控制路径。

### 13.4 接真实工程前必须确认

1. **总线拓扑**：CPU侧AXI master经interconnect/必要的Full-to-Lite转换访问CSR；renderer的AXI Full master与CPU内存主口共同访问DDR3，不能把两个master直接短接到同一slave。
2. **DDR3配置**：MT41J128M16JT-125、x16、256MB等参数仍须与板卡原理图/BOM核实；用户侧AXI宽度/ID/频率以生成IP为准。本轮不猜测球位和IO电压。
3. **DDR init与显示启动**：AXI新请求已受`ext_mem_init_done/error`门控，但板级仍须保证复位/视频使能在校准及首次预取完成后释放；不能仅凭请求门控保证上电无显示欠载。
4. **CDC与HDMI**：page CDC、display memory CDC、PLL/复位、HDMI PHY仍为真实IP/实现空位。640×480 timing存在不等于TMDS/HDMI已经完成。
5. **CPU缓存一致性**：CPU生成图像/命令、硬件写回与CPU基准渲染共享DDR时，需要非缓存区域或cache flush/invalidate及必要内存屏障。
6. **性能边界**：当前一次仅处理一个抽象内存事务，renderer每行先读再写；Color Key完整读取背景。没有基于板卡实测的FPS或Sprite数量保证。先跑基础Demo，再按计数器/STA结果决定DSP、burst长度、FIFO深度和调度优化。

本轮交付范围是必要的板卡无关RTL重调及可追溯文档，不包含烧板、虚构IP连线或把空黑盒视为已完成外设。

一、先看这几项

本包以你上传的 FIX 压缩包为基线，集中修改 FPGA 中的几何识别和边缘降噪、稳定算法。不是换用此前未经修复的 V12，也不是把几何识别搬到电脑上计算。

电脑软件沿用原 V12 已修复的控制台，整个软件目录逐文件校验保持一致。窗口仍显示“第十二版”，协议仍为 12，这是有意保留兼容性。只替换电脑软件、没有给板卡下载本包的新 bit 文件，不能获得本轮算法变化。
开发测试文件中的 V13 是本轮内部编号；对外交付包统一称为 V12 增强版，不表示需要另换协议或控制台。

没有删除模式、TRAIL、CONTOUR、MOTION、灰度分屏、冻结回放、两帧比较、人脸辅助等功能；阈值输入、文字菜单开关、鼠标选区和各项按键操作继续沿用。原 FIX 中的摄像头初始化、DDR 采集及诊断信息也保留。

交付前完成的仿真、资源、时序和包校验，见“本轮验证结果.txt”及包内“验证结果.json”。本轮没有连接你的实际 Ti60 板卡、摄像头和采集卡，不能把合成测试结果当成拍屏实测结果，也不承诺所有屏幕、所有距离都没有闪烁或噪点。

6. 验证记录、验证结果.json、SHA256SUMS.txt：本轮验证证据与文件完整性校验。

先保存当前能工作的 FIX 下载文件。保持摄像头和显示接线不变，用 Efinity Programmer 给板卡下载本包 V12_PLUS_20261025.bit。下载完成后打开控制台，选择原来的采集卡和串口；启动视频、连接板卡。使用和原 FIX 相同的下载方式，是否写入 Flash 沿用你原来的方法。

接线继续采用：
摄像头 → FPGA → HDMI 有源分配器 → 独立显示屏
                              └→ 采集卡 → 电脑 USB
电脑 USB 串口 ↔ FPGA

电脑预览读取 FPGA 最终 HDMI 画面，因此板卡上的几何描边、菜单、边缘效果也会出现在电脑上。采集卡会引入延迟，两个屏幕不保证同一时刻显示同一帧；本轮没有改变该架构。直接使用控制台时，关闭占用同一采集卡的 OBS 等应用。

三、怎样测试屏幕上的几何图形

先使用“模式0 彩色原图”检查摄像头是否合焦：屏幕上的笔画不能已经糊成一片，也不应出现大片白色过曝。软件中的边缘滤波无法恢复镜头没有拍清楚的细节。

建议先在另一块屏幕全屏打开随包的“屏幕几何演示图.png”。先测一个图形，再测多个；不要把控制台自身预览窗口当作测试目标，以免形成画面反馈。

建议步骤：
1. 固定摄像头和测试屏幕。适当转动屏幕或移动灯光，让灯、窗户的反光避开测试区域。
2. 在控制台图像页选 Sobel 或 Canny 边缘模式；中值选“选择中值”，时域稳定开启。先保持其他选项与原 FIX 一致，以便比较。
3. 使用鼠标拖动选区，围住待识别图形并留出完整轮廓周围的空白。不要把图形切到选区外，也不要让屏幕边框、任务栏、文字标签与图形轮廓连在一起。
4. 开启目标图形识别，等待几个完整处理结果。颜色保持：黄色＝圆/椭圆，蓝色＝矩形，绿色＝三角形，粉色＝平行四边形。
5. 若图形边缘都没检测出来，先调整阈值。默认值为 192，允许范围 16～1024；以每次 16 或 32 的幅度调整，点击应用并确认板上菜单已显示新值。弱边不完整时降低；背景密集碎点很多时略升。这里给的是操作顺序，不是对所有屏幕通用的最佳阈值。
6. 若边缘已清楚但仍不分类，先把选区缩到单个图形，确保轮廓完整；再尝试改变距离或屏幕显示大小。大选区缩小到识别网格后，小图形会失去角点与曲率信息。
7. 在正视、轻微倾斜和旋转条件分别观察；允许局部小缺口不代表可以识别任意遮挡、重叠或严重透视变形。

本轮修正集中于：粗边、双边造成的三角形漏检，斜向小缺口的连接，以及部分厚线、旋转椭圆漏检。降噪由前级保边平滑和时域稳定负责；几何缩小分析保持原来的边缘占据采样，优先保住细弧切点。圆/椭圆仍合并为一类，不恢复两类之间跳色的旧行为。矩形和平行四边形的命名与颜色不变。

四、怎样比较边缘优化效果

使用同一摄像头、同一屏幕亮度、同一距离、同一阈值与滤波配置，对照原 FIX 与本包。不要一边改变拍摄条件、一边比较算法，否则无法判断改善来自哪里。

推荐同时观察三类目标：
1. 均匀灰底加细黑线：看灰底的散点和线条是否抖动。
2. 小字与低对比浅灰线：看笔画是否仍然存在，不能只看边缘数减少。
3. 缓慢移动的图形：看新边是否跟上、旧位置是否拖影。

本轮在原选择性平滑和时域稳定模块中优化，复用已有历史信息，没有增加整帧片上缓存。稳定判断更重视当前边缘的空间连续性和相邻帧重复证据，减少屏幕亮度波动直接放过瞬时杂点的情况。只有新增或不稳定的短边可能需要后续帧确认；不把故意显示历史的 TRAIL 效果改成普通边缘。

选择中值、保边双边、时域稳定仍可按原方式单独开关。普通中值更容易损失极细线；多个平滑同时开启也可能减弱低对比细节。需要看细字时优先从选择中值和时域稳定开始，再单独比较双边开关。模式0的彩色底图不是普通边缘显示，观察降噪应使用 Sobel/Canny 模式。

屏幕像素网格、摩尔纹、摄像头增益噪声与真实细线有时具有相近的空间尺度。不存在既无条件删除所有这类噪声，又无条件保留所有微弱笔画的过滤条件。本轮测试结果保留低对比细线的取舍和不利工况，详见算法验证说明，不把“更稳定”写成“绝对无闪烁”。

五、拍屏时比盲目调阈值更有效的调整

尽量降低环境反射：改变灯光方向、屏幕角度，避开背后的亮窗，避免镜头正对屏幕反射的灯。
让屏幕图形足够大，但不要近到超出镜头能合焦的距离。小字看不清时，先用原图确认焦点，再考虑调算法。
如果看到密集条纹或随距离变化的彩色波纹，轻微改变摄像头距离或角度再观察。这类摩尔纹不能保证靠本轮算法消除。
保持测试屏幕亮度稳定。不要在屏幕忽明忽暗、自动亮度频繁调整时同时比较算法；本轮没有修改摄像头曝光寄存器或屏幕刷新设置。
先用干净黑白几何图形确认识别链路，再增加彩色、复杂背景或倾斜程度。反光边界也是实际亮暗边缘，单纯升高阈值可能同时删掉真实细节。

七、若下载后异常

如果独立显示屏和电脑预览都只有菜单、没有摄像头画面，先拍下 FIX 保留的诊断字符及状态；不要据此把问题归为采集卡没启动。若独立屏正常而电脑停住，则先排查电脑采集设备占用、实际帧率和 USB 连接。
几何识别无结果时，分别记录原图是否清楚、边缘是否完整、选区大小、模式、阈值、滤波开关和测试图形。截图能反映空间噪点，短视频更适合判断闪烁与跳色。
本包保留原 FIX 的采集与 DDR 路径，但未在你的实板上验证；若出现新增问题，请保留相同接线下原 FIX 与本包的对照结果。

八、重新编译

用安装的 Efinity 打开 FPGA_engin/Case4_Ti60.xml。自动流程可在包根目录 PowerShell 执行：
powershell -ExecutionPolicy Bypass -File .\tools\compile.ps1 -Python python -EfinityRoot "D:\" -Bitstream

EfinityRoot 必须指向本机含 bin/efx_run.bat 的安装根目录；上例是本次构建环境的路径。Python 需要可执行本包构建检查工具。本包 FPGA 工程自身包含 RTL、IP、初始化文件和约束，不依赖开发者原始工程目录。
不要删除八个 DDR carry-chain 物理约束，不要降低时钟频率来替代时序验收；脚本会检查所有时钟关系、实际布局位置、资源、源文件与 bit 文件一致性。开发源码中的回归脚本是开发验证材料，包含本机工具路径，迁移机器时需要设置相应工具路径。

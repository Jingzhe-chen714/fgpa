V13 基线及功能保留核验说明

1. 本轮基线
本轮以用户提供的 Case4_Ti60_1080p_V12_FIX_20261022.zip 为准。
原压缩包 SHA-256：59e268054e40d5dd6f14b60f5228f0eb72a00eb58510477a88bf6a90f3c2e888。
该版本实际是 V12 诊断版 D1。其说明明确写明：增加无有效帧提示与摄像头、DDR 诊断，不能将它描述为已经经实板验证消除黑屏的版本。
本轮只允许修改几何识别及边缘处理相关实现，不改变其他功能。

2. 必须继续保留的 D1 行为
持续没有有效摄像头原始帧时，显示“图像异常”。
四行 D1 十六进制诊断保留，并继续独立于常规文字菜单开关。
摄像头观察计数、I2C NACK 观察和 DDR 写入提交计数保留。
摄像头寄存器表、原图采集、DDR IP 与读写框架、物理引脚及 PLL 不因本轮识别优化而替换。

器件 Ti60F225。

4. 源码保留核验
scripts/audit_v13_preservation.py 对照附件基线，核验以下内容：
（1）基线源文件与原 D1 验证记录匹配。
（2）只允许几何分类、梯度、空间去噪、边缘连接和时间稳定相关 RTL 文件发生变化。
（3）保护串口协议、按键控制、阈值入口、菜单、分屏、回放、双帧、原图、Gamma、双边滤波、人脸绘制与 D1 诊断文件。
（4）最终工程的顶层、摄像头源文件、DDR/IP、引脚与时钟约束对照 D1 保持一致。
（5）工程 XML 文件引用必须存在且位于工程目录内；已暂存 RTL 必须与开发源码一致。
（6）可对照原 V12 电脑软件目录，核验源码及 EXE 运行目录未更改。
这些是源码及包一致性检查，不等同于识别准确率、动态画质或实板运行验证。

5. 构建与交付证据要求
不能沿用附件的 PASS 结果来证明修改后的 RTL。
创建新构建目录时，应清除复制过来的旧 outflow、旧验证报告、旧位流和旧 placement_db，保留实际源文件、IP、约束和原 8 个位置约束输入。
必须重新完成综合、接口生成、约束检查、布局布线、建立/保持时序检查、实际物理位置核验、位流生成及源文件绑定。
Efinity 进程退出码为 0 也不代表时序通过，必须检查所有时序关系没有负裕量。
最终 FPGA_engin、开发源码、烧录文件和验证报告应绑定同一组源码哈希。
电脑软件沿用 V12 协议和程序时，应明确说明其窗口仍显示第十二版；不能仅为改名称而偷偷更换行为。

6. 工具路径
附件 tools/compile.ps1 的默认 Efinity 目录为 D:\Efinix\2026.1。
本次开发主机实际可用的运行器位于 D:\bin\efx_run.bat，应显式传入 -EfinityRoot D:/。
用户重新编译时应指定自己实际安装的 Efinity 路径；这些绝对路径不是工程源文件依赖。
